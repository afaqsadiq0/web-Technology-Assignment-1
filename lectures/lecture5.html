User Input & Forms

HTML Forms

The primary mechanism for two-way user interaction on the web. Exploring form controls, input validation, accessible label associations, submission HTTP methods, and an interactive demonstration form.

🎯 Learning Objectives

  • ✓ Understand the <form> tag, action targets, and GET vs. POST methods.
  • ✓ Associate accessible <label> tags with controls using the for attribute.
  • ✓ Implement text, email, password, radio, checkbox, and select elements.
  • ✓ Validate client input using native HTML5 attributes (required, pattern).

# 1. Form Structure & HTTP Methods

An HTML Form is a document section containing interactive controls designed to collect data from a user and transmit it to a web server for processing.

The container element is <form>, which configures the submission destination and network transmission protocol:

HTML Example — Form Definition & Attributes 
<!-- Form submitting data securely to a server endpoint -->
<form action="/api/register" method="POST" enctype="application/x-www-form-urlencoded">
  <!-- Form controls go here -->
</form>
  • action: The URL of the server-side script or API endpoint that will receive and process the submitted data.
  • method="GET": Appends form values directly into the browser URL query string (e.g., ?query=html). Suitable for idempotent search queries; never use for passwords or sensitive data.
  • method="POST": Transmits data inside the HTTP request body payload. Essential for secure data, passwords, file uploads, and state-modifying actions.

# 2. Labels, Inputs & Controls

Form accessibility relies upon explicit label binding. The <label> tag's for attribute must strictly match the unique id of its corresponding input element:

HTML Example — Text, Email, and Password Inputs 
<!-- Text Input with Explicit Label Binding -->
<label for="userName">Full Name:</label>
<input type="text" id="userName" name="user_name" required placeholder="Muhammad Afaq">

<!-- Built-in HTML5 Email Validation -->
<label for="userEmail">Email Address:</label>
<input type="email" id="userEmail" name="user_email" required>

<!-- Password Masking Input -->
<label for="userPass">Password:</label>
<input type="password" id="userPass" name="user_password" minlength="8">

Selection Controls & Multi-line Text

  • Radio Buttons (type="radio"): Used when a user must choose exactly one option from a mutually exclusive set. All radios in a group must share identical name attributes.
  • Checkboxes (type="checkbox"): Used for binary toggles or selecting multiple independent options simultaneously.
  • Dropdown Select (<select> & <option>): Space-saving menu revealing a list of options when clicked.
  • Multi-line Textarea (<textarea>): Resizable multi-line text input for extended comments, essays, or feedback.
  • Submit and Reset Buttons: <button type="submit"> initiates form validation and HTTP dispatch; <button type="reset"> restores all fields to initial default values.

🚫 Solution: GET Security Pitfall
When using method="GET", all form inputs are appended in plain text to the URL string (e.g. /login?user=afaq&pass=secret123). This causes passwords to be permanently recorded in browser histories, proxy logs, web server access logs, and HTTP Referer headers. POST keeps the payload inside the HTTP request body.
🔘 Solution: Radio Button Mutual Exclusion
Radio buttons belong to a unified group only when they share the exact same name attribute (e.g. name="shift"). The browser then automatically unchecks any other radio button in that group when the user selects one. Each individual button specifies its distinct payload via the value attribute.
🏷️ Solution: Label Binding & Tap Targets
Pairing <label for="userEmail"> with <input id="userEmail"> provides two huge benefits: (1) When a user taps or clicks the textual label, the browser automatically focuses the input or checks the checkbox (massively boosting mobile usability); (2) Screen readers announce the label text immediately upon focusing the control.
🛡️ Solution: Defense-in-Depth Validation
Client-side HTML5 validation (e.g. required, pattern) is strictly a User Experience (UX) convenience to assist honest visitors. Anyone can bypass client-side checks in 5 seconds using Browser DevTools or sending HTTP requests directly via cURL or Postman. Therefore, server-side validation is mandatory to prevent SQL Injection and malicious payloads.

Key Takeaways: Lecture 05

  • › Always pair <label for="..."> with <input id="..."> for accessible screen-reader interactions.
  • › Use method="POST" for forms conveying sensitive credentials or database mutations.
  • › Radio buttons share identical name attributes to enforce single selection; checkboxes allow multiple selections.
  • › Native HTML5 validation attributes (required, type="email", minlength) prevent invalid data dispatch.
