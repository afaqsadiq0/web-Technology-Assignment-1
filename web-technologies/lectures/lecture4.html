Document Structure

Block, Inline & Semantic HTML

Mastering display models in the browser DOM. Understanding the differences between block-level and inline elements, structural semantics, accessibility advantages, and modern HTML5 page layouts.

🎯 Learning Objectives

  • ✓ Distinguish between block-level and inline elements in visual flow.
  • ✓ Compare CSS dimension and margin behavior across display models.
  • ✓ Identify common semantic HTML5 structural tags and landmarks.
  • ✓ Construct accessible page wireframes replacing generic <div> soup.

# 1. Block-Level Elements

A block-level element always starts on a new line and automatically expands to fill the entire horizontal width of its parent container (100% width by default). Block elements stack vertically down the webpage one after another in the normal document flow.

Common block-level elements include: <div>, <p>, <h1>-<h6>, <ul>, <ol>, <li>, <section>, <article>, <header>, and <footer>.

HTML Example — Block Elements Stacking Vertically 
<!-- Each block element begins on a new line and occupies full available width -->
<div style="background-color: #dbeafe; padding: 10px;">First Block (100% width)</div>
<div style="background-color: #bfdbfe; padding: 10px;">Second Block (stacks below)</div>

# 2. Inline Elements

An inline element does not cause a line break to appear in the document. It only consumes as much horizontal width as necessary to wrap its immediate content. Inline elements flow horizontally side-by-side alongside adjacent words or other inline elements until they encounter the edge of the containing box, where they wrap naturally.

Common inline elements include: <span>, <a>, <strong>, <em>, <code>, <img>, <label>, and <input>.

HTML Example — Inline Elements Flowing in Prose 
<p>
  This is normal prose containing an
  <strong>inline strong tag</strong>, an
  <a href="#">inline hyperlink</a>, and a
  <span style="color: #2563eb;">styled inline span</span>.
</p>

# 3. Block-Level vs. Inline Elements Comparison

Understanding the layout physics of both display categories is critical to mastering CSS layouts:

Behavioral Characteristic Block-Level Elements Inline Elements
Default Line Break Always begins on a fresh new line. Flows inline with adjacent text without line breaks.
Default Width Expands to 100% of parent container width. Shrinks to fit the exact width of its inner content.
Explicit Width & Height Respects CSS width and height properties. Ignores CSS width and height properties.
Vertical Margins & Padding Top and bottom margins and padding fully push surrounding elements. Top and bottom padding renders visually but does not push adjacent lines. Top/bottom margins have no effect.
Permitted Nesting Can contain other block elements as well as inline elements. Can contain other inline elements and text data (avoid nesting blocks inside inline).
Canonical Examples <div>, <p>, <h1>, <section>, <article> <span>, <a>, <strong>, <em>, <code>

# 4. Semantic HTML & Core Structural Elements

A semantic element clearly describes its meaning to both the web browser and the human developer. In legacy HTML, developers constructed entire layouts using non-semantic <div class="header">, <div class="nav">, and <div class="footer">—a problem known as "div soup".

HTML5 solved this by introducing dedicated semantic layout elements that define recognizable landmark regions:

<header>

Contains introductory content, site logo, candidate titles, or primary search bar.

<nav>

Designates a major block of navigational links intended for site or page exploration.

<main>

Encapsulates the dominant, unique content of the document (only one per document).

<article>

Self-contained, reusable composition independently distributable (e.g., blog post, lecture).

<section>

Represents a standalone thematic grouping of content, typically introduced by a heading.

<aside>

Content tangentially related to the main topic, such as sidebars, glossaries, or author bios.

<footer>

Contains author information, copyright metadata, legal links, and secondary navigation.

<figure> & <figcaption>

Encapsulates illustrative media (images, diagrams, code blocks) with an accessible caption.

Semantic HTML5 Layout Architecture

The visual wireframe below illustrates the semantic hierarchy of a modern web page:

<header> — Site Header, Logo & Branding
<nav> — Main Navigation Menu Links</nav>
<main> — Unique Central Content
<article> — Independent Educational Article / Module
<section>Thematic Subsection</section>
<aside> — Contextual Sidebar (Glossary, Student Info, Related Links)
<footer> — Institutional Copyright, Student Metadata, Course Affiliation

# 5. Why Semantic HTML Matters

  • Digital Accessibility (a11y): Assistive technologies (screen readers like NVDA and JAWS) construct landmark shortcuts from semantic elements, allowing visually impaired users to jump directly to <main> or skip navigation menus.
  • Search Engine Optimization (SEO): Web crawlers (Googlebot) parse semantic headings and articles to understand the conceptual hierarchy and primary topic of each page, directly improving search rankings.
  • Maintainability & Developer Ergonomics: Reading <nav> or <article> conveys immediate developer intent compared to analyzing dozens of nested <div> wrappers with arbitrary class names.
★

Key Takeaways: Lecture 04

  • › Block-level elements take up the full horizontal width and always start on a new line.
  • › Inline elements wrap content tightly and do not accept CSS width/height dimensions.
  • › Semantic tags (<header>, <nav>, <main>, <footer>) replace non-descriptive <div> soup.
  • › Proper semantic markup improves web accessibility, SEO indexing, and source code maintainability.
