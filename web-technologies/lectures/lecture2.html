System Design & Architecture

Tiered Web Architecture

A deep architectural analysis of software layering in web systems. Examining the structure, component separation, scalability trade-offs, and use cases of 1-Tier, 2-Tier, and N-Tier architectures.

🎯 Learning Objectives

  • ✓ Distinguish between functional layers (logical) and physical tiers.
  • ✓ Analyze the monolithic structure and limitations of One-Tier systems.
  • ✓ Examine Two-Tier client-server dynamics (Thick vs. Thin clients).
  • ✓ Evaluate N-Tier (3-Tier) enterprise systems for scalability and security.

# 1. What is Tiered Web Architecture?

In software engineering, Tiered Architecture refers to the structural organization of an application where functional responsibilities are separated into distinct physical or logical layers. Each tier delivers a specialized service and communicates with adjacent tiers through clearly defined interfaces.

A fundamental distinction exists between layers and tiers:

  • Logical Layers: Conceptual separation of code responsibilities (e.g., UI code, business logic functions, database queries) within software codebases.
  • Physical Tiers: Physical separation of software execution across distinct physical or virtual machines on a computer network.
💡 The 3 Canonical Application Layers

Virtually all modern web applications consist of: (1) Presentation Layer (User interface and client interactions), (2) Application / Business Logic Layer (Calculations, domain rules, and data processing), and (3) Data Layer (Persistent storage, relational databases, or file systems).

# 2. One-Tier (Single-Tier) Architecture

In a One-Tier Architecture, all software layers—the presentation interface, business logic, and database storage—reside and execute within a single physical machine or device. There is no network communication required to process transactions.

One-Tier Architectural Topology

Single Physical Computer / Local Host
Desktop Machine / Workstation
1. Presentation Layer (UI)
GUI / Terminal Display
2. Business Logic Layer
Internal Calculations & Rules
3. Data Storage Layer
Local SQLite, MS Access, or Flat Files

Key Characteristics

  • Zero Network Overhead: Because everything is colocated, execution speed is high and there is zero transmission latency.
  • Simplicity: Easiest to install and configure; no web servers or firewalls are required.
  • Critical Disadvantages: Cannot be shared across multiple concurrent users; software updates must be installed manually on every individual machine; difficult to scale.
  • Common Use Cases: Local spreadsheets (MS Excel), desktop word processors, standalone SQLite database tools, local media players.

# 3. Two-Tier Architecture (Client-Server)

A Two-Tier Architecture separates the system into two distinct physical endpoints: a Client Tier and a Database Server Tier, communicating over a local area network (LAN) or the Internet.

Two-Tier Architectural Topology

Tier 1: Client Node
User Workstation

Presentation Layer + Application Logic (Thick Client)

↔ Network / SQL Queries
Tier 2: Database Server
DBMS Server

Data Layer (Relational Tables, Stored Procedures)

Thick Client vs. Thin Client

In a classic 2-Tier setup, the client is usually a Thick (Fat) Client where both the user interface and the business logic are compiled into the client desktop software. The client software connects directly to the remote database via ODBC/JDBC.

  • Advantages: Centralized database storage ensures multiple users access identical data simultaneously; high performance for dedicated LAN setups.
  • Disadvantages: Poor security because database credentials or ports must be accessible to clients; difficult maintenance when updating business logic; limited scalability due to direct database connection limits.
  • Common Use Cases: Legacy banking branch software, internal corporate ERP inventory systems running over private local company networks.

# 4. N-Tier (Three-Tier) Web Architecture

Modern web systems adopt an N-Tier Architecture (most commonly structured as a 3-Tier Model). Here, business logic is completely decoupled from both client devices and the persistent database, running on dedicated application web servers.

Three-Tier Web Architecture Topology

Tier 1: Client
Presentation Tier

Web Browser (HTML5, CSS3, DOM UI)

↔ HTTP / HTTPS
Tier 2: Server
Application Tier

Web & Business Logic Server (Node, Python, Java)

↔ TCP / SQL / ORM
Tier 3: Storage
Data Tier

Database Management System (PostgreSQL, MySQL)

Component Breakdown of the 3 Tiers

  • 1. Presentation Tier (Frontend): Runs on the client's browser. Responsible for translating user actions into HTTP requests and rendering HTML/CSS visual outputs. It has zero direct access to the database.
  • 2. Application / Logic Tier (Middle Tier): The engine of the web system. Evaluates business rules, validates incoming request parameters, enforces security authentication, and determines what data to fetch or modify.
  • 3. Data Tier (Backend Storage): Dedicated DBMS (e.g., MySQL, Oracle, MongoDB). Handles ACID transaction safety, storage persistence, and indexing, shielded safely behind private firewalls.
🛡️ Major Security Advantage of 3-Tier Systems

In a 3-tier architecture, the client never communicates directly with the database. The database server resides inside an isolated private subnet, completely shielded from public Internet traffic, preventing direct SQL port exploits.

# 5. Comprehensive Architectural Comparison

The table below contrasts the three major architectural patterns across scalability, security, development complexity, and maintenance parameters:

Evaluation Metric One-Tier Two-Tier N-Tier / 3-Tier
Physical Nodes 1 (All-in-one local host) 2 (Client & Database Server) 3 or More (Client, App Server, DB)
Scalability None (Restricted to 1 user) Low (Database connection bottlenecks) High (Horizontal scaling via load balancers)
Security Posture High local; No network risk Weak (Clients talk directly to DB) Excellent (DB protected behind app tier)
Maintenance Cost High (Update every device) Moderate (Update client software) Low (Update central web server code)
Network Dependency Zero network needed High LAN dependency Internet / WAN optimized
Standard Web Fit Unsuitable for Web Limited (Intranet tools) The standard for all modern web apps
★

Key Takeaways: Lecture 02

  • › Tiers represent physical separation across hardware, while layers represent logical software modules.
  • › One-Tier systems bundle UI, logic, and data locally; they cannot support modern distributed web clients.
  • › Two-Tier systems introduce network client-server communication but expose databases directly to clients.
  • › Three-Tier/N-Tier is the gold standard for the modern Web, ensuring horizontal scaling, security isolation, and code maintainability.
